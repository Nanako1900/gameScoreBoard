## 配置与凭据契约

沿用 `GET/POST /api/admin/ai-config` 和 `POST /api/admin/ai-config/test`，均仅管理员可用，响应使用 `private, no-store`。

写入增加 `api_key?: string | null`：省略表示保持现有凭据；非空字符串表示替换；`null` 表示明确清除。先对原字符串拒绝 NUL/CR/LF（包括首尾换行），再去除前后空白，拒绝空值或超过 4096 字符的值。

读取继续返回 `has_api_key`，新增 `api_key_source: 'database' | 'environment' | 'none'`、`configured_enabled: boolean`、`can_update_api_key: boolean`。`enabled` 保留“实际可用”的旧语义，开关改读 `configured_enabled`，避免缺少 Key 时误把用户的启用意图改为关闭。服务端总是返回新增元数据；前端类型将新增字段设为可选以兼容旧后端，缺少设置能力字段时不开放 Key 写入。`disabled_reason` 返回固定、可操作的中文原因。任何读取、保存、试跑响应均不返回凭据明文或密文。

保存先完成全部字段校验与加密，再用一次 `db.batch()` 原子提交；任一校验或数据库语句失败，所有字段保持原值。沿用已有 `updated_by`、`updated_at`，不记录密钥内容。

## 加密与过渡规则

- 新增逻辑键 `ai.api_key_encrypted`，值为版本化 JSON。设置态为 `{v:1,state:'set',iv,ciphertext}`，清除态为 `{v:1,state:'cleared'}`；不接受旧的明文 `ai.api_key` 行。
- 主密钥是 Base64 编码的 32 字节随机值。使用 Web Crypto AES-256-GCM，每次随机生成 12 字节 IV，128 位认证标签，固定 AAD `edg-credit:ai.api_key:v1`；IV 与密文使用 Base64。
- **不存在凭据行**时，兼容旧 `AI_API_KEY`。存在设置态时只用数据库凭据；存在清除态时不再回退旧环境 Key。其他普通字段继续沿用数据库 > 环境变量 > 默认值。
- 未配置主密钥时，旧环境配置仍可运行，普通配置仍可修改；设置新 Key 返回可操作的服务配置错误，不产生任何写入。清除操作不需要解密能力。
- 已有数据库密文却缺少/用错主密钥、密文损坏时，停止使用该凭据并标记 AI 不可用，不偷偷回退旧 Key。业务使用既有 AI 失败回退；`/api/config` 和首页不能因解密异常返回 500。
- `loadAiConfig` 每次读取已提交配置，不增加进程缓存。app 与 bot 使用相同数据库和主密钥；已发出的 AI 请求完成后，后续请求使用新配置。

## 页面行为

保留现有 AI 设置布局、提示词与近 7 天统计，增加 Key 的“已设置 / 未设置”和来源状态。密码框不回填原值；普通保存省略 `api_key`。更换时输入新值；为本页新增清除的两步确认，复用项目既有确认交互模式，并明确会停止 AI、转入既有回退逻辑。`can_update_api_key=false` 只禁用设置/更换；包括密文解密失败时在内，清除仍可操作。旧后端缺少新增元数据时不开放新增清除操作。

Key 只在组件内存中短暂存在，不进入 URL、草稿、浏览器存储或日志。保存完成、请求失败、组件卸载、切账号或失去权限时清空输入；成功写入后的刷新失败要提示“修改已保存，状态刷新失败”，不能谎报保存失败或自动重复写入。

试跑仍使用已保存配置，按钮说明这一点；有未保存改动时提示先保存，不新增草稿试跑接口。试跑不修改任何人的分数。

## 防止回显

分类、量刑、周报三条 AI 客户端统一过滤当前 Key 的精确文本，再将上游内容用于错误、审计、判词或周报。配置错误使用固定文案；试跑响应不再返回原始 `raw`。不记录请求体、Authorization 或加解密材料。

## 范围与验收

本期保持一个全局 OpenAI 兼容配置；不增加多提供商配置档案、模型目录、按业务指定模型、主密钥在线轮换或外部 Vault。保留两阶段裁判、夹取与失败回退规则。

验收包括：无任何 AI 提供商环境变量时可从网页配置成功；普通保存保留 Key；更换后 app/bot 下一次调用用新 Key；清除不恢复旧环境 Key；失败无部分写入；非管理员无访问权；响应、日志和审计不含测试 Key；主密钥故障不导致首页崩溃；D1 与 PostgreSQL 行为一致。

上线需一次性在 app、bot 透传同一 `AI_CONFIG_MASTER_KEY`，随后 Redeploy。主密钥需独立持久保存与备份，不能随部署随机生成。旧环境 Key 在完成网页、bot 验收前保留作兼容；数据库已有凭据后它不再生效。无需 SQL 迁移。
