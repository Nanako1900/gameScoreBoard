# C5 · 房管响应、控制卡可靠性与固定房管理

2026-10-29。基于 `6d218c6`（main #46）开工。机主反馈建房可用但响应慢、房内卡未出现，并要求现有私人固定房自动补卡。

## 1. 已确认政策

- 临时房不再限制房主操作：当前服务器成员只要能查看房间即可使用所有已有控制；Bot、离服者和不可见私房仍不开放。保护 Bot／工作人员、移动前检查与有人房安全解散规则保留。
- 固定房由网页管理员使用 Discord 用户 ID 分配管理者。ID 是管理员主动输入的例外，仅服务端匹配，不通过 GET、日志或错误回显。仍使用随机引用作为网页选择器与公开资源标识。
- 固定房分类由网页管理员明确选择，其中现有语音房自动登记并补卡，排除创建入口／等候区／已登记临时房。固定房不回收、不转让／认领，不提供删除频道功能；分配管理者不自动授予 Discord 查看权限。
- 临时房空房回收、审计找回、语音证据和所有既有业务／隐私约束继续保留。

## 2. 实施顺序

每步先失败测试再实现，通过后按 `<type>: <中文>（C5）` 提交，无署名。

1. 修复新房丢失分类中 Bot 消息权限；并行独立读取、去除重复上下文和紧邻重复检查。每次副作用仍新鲜鉴权，无跨操作权限缓存。
2. 同频道静音事件不触发房管；建房入口不等待全服房间维护；目录事件合并，保留立即失效和同步代次保护。同步期间收到的真实入口事件在同步成功后按实际位置重试。
3. 固定房可信登记、完整可见范围投影、Bot 消息自动补建；与临时房配额／回收／所有权分开。旧设置兼容，未知结果继续保守。
4. 临时共享操作和固定分配管理者统一覆盖 Discord／HTTP；写前重查身份、可见性和版本。控制卡错误可诊断，状态变化及时重试、新卡优先。
5. 网页分类选择和固定管理员 ID 输入／替换／清空，保留五项常用设置、草稿与权限隔离；不回填输入 ID。
6. 更新契约、使用和验收记录，跑八类全量及 server build。只交付代码和本机验证，提 PR 后停下。
