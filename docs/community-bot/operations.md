# 社区功能 · 使用、管理与上线验收

本 PR 交付代码和本地验证。**尚未部署，也未执行任何远程迁移或 Discord 操作。**

PR #44 已基于 `3119a96`（main #43）融合 S6 清爽总览，下面入口沿用其单一主导航、集中设置与整页详情。融合后本地复核状态见 [validation.md](validation.md)，不将原验证记录视为本轮已重跑。

## 成员入口

- Discord `/room`：建房、加入与管理房间；加入指定建房语音入口也会建房。
- `/roles`：多选兴趣身份，取消选中即可退出。超过 25 个候选时分页，其他页的选择会保留。
- `/poll`、`/teams`、`/draw`、`/roll`、`/topic`、`/room_ai`：投票、主动选人分队、不放回抽签、骰子、题库与主动 AI 建议。
- 控制面板中的三个按钮打开各人的私密操作界面；趣味结果可从“趣味工具 → 近期结果”再次打开。投票截止前可以改票，重抽会保留旧结果。
- 网页首页 → **社区中心**，或 `/community`、`/community/roles`、`/community/play`。网页成员操作需登录 Nanako、绑定自己的 Discord 且仍在服务器内；Discord 内使用无需绑定。Nanako 管理员无需绑定也可配置社区和管理已有房间。
- 全局主导航 → **设置** (`/settings` 默认个人资料) 集中名字、身份、绑定与私信偏好；成员与 AI 管理沿用 `/settings/members`、`/settings/ai`。头像菜单只保留「我的记录」「退出登录」。首次入户仍走 `/welcome`，所有旧深链保留原行为，裁判工具仍从案件页进入。

创建或加入网页／按钮指定的语音房前，先连接服务器内的语音。Bot 不会替离线成员开始语音；等待过程中位置改变时，不会用旧请求把人拉回。

每人最多一间。默认公开可加入；房主可锁门或隐藏、控制人数、允许／禁止成员、移出当前房间中的成员。转让只发送邀请，对方接受才改变房主；对方必须已经能查看房间，邀请 5 分钟失效。房主离开 120 秒后，仍在房内的成员可主动认领。

空房默认 120 秒回收；有人重入、快照不完整或 Gateway 断线时不删除。恢复后重新观察宽限，不把离线时段推断为一直空房。房主只能解散空房。管理员关闭有人房，必须二次确认，先将所有人移往配置的等候语音频道；任一步失败都保留房间。

房间访问模式不改变既有语音记录规则：真实移动仍由原记录器记录，隐私、覆盖、保留期与查看权限不变。

## 集中管理

Nanako 管理员从 **设置 → 社区管理** (`/settings/community`，兼容 `/admin/community`) 配置：

1. 总开关，以及建房分类、入口、等候区、面板频道、人数与宽限。
2. 公开入服欢迎频道、模板、预览和重入冷却（默认 24 小时）。只有新入服事件触发，不补发给启动时的全体成员；零自动提及、零额外入服私信。既有绑定欢迎私信独立保留。
3. 自选身份安全白名单，每人上限 1–5；托管、高权限、机器人层级以上的角色不会开放。只移除本模块赋予的身份，不接管管理员原有分配。暂停或撤白名单后仍可退出；角色本身变成高权限时，需管理员在 Discord 处理，Bot 不擅自删除。
4. 六种趣味工具、冷却与参数上限、话题正文和标签。
5. 社区 AI 独立开关、提示词和每日配额。凭据与模型由 **设置 → AI 模型与密钥** (`/settings/ai`，兼容 `/admin/ai`) 管理；关闭“启用 AI 量刑”不等于关闭社区 AI。
6. 已保存／已应用版本、Bot 同步状态、资源目录刷新、面板刷新、操作记录和审计。

开关暂停新建／新领，已有房间仍可安全管理，已选身份仍可退出。裁判没有新增社区管理员权限。只读模式拒绝提交与执行社区修改。

`202` 只是排队。网页显示排队、执行中、已执行、失败、冲突、取消和待对账；只有实际执行回执才显示完成。失去身份／权限或换账号后，旧页面数据、旧操作结果和迟到请求不会继续显示。

AI 只用本次主动输入，不读取聊天、案件或语音证据。默认按 `RESET_TZ_OFFSET` 日界线每人 5 次、全服 50 次；失败也计配额，提供商不可用时返回题库备用建议。没有房间范围的 AI 结果仅本人和管理员可见；房间内结果继承房间可见范围。改名需要另一次明确确认。

## 待对账

操作执行结果不确定时，队列停止重放同范围任务。该房间会隔离，其他普通成员不会根据旧访问模式看到它。管理员先在 Discord 检查实际频道、成员位置、角色和消息，再在网页展开 **人工核对并取消旧任务**，二次确认后：

- 只将旧任务记为已人工核对、取消并解除队列阻塞，记录审计；不重放 Discord 动作。
- 欢迎按已发送计入冷却，避免立即重复欢迎。
- 不直接恢复房间。刷新服务器目录后，只有已登记频道的类型／分类／Bot 与房主访问权限、完整访问模式可重新核验时才恢复；恢复会重建实际名称、人数限制和成员 ACL。
- 建房回执丢失，只认本 Bot 的 `community-room:<operation ref>` 审计标记。完整扫描且唯一匹配才收养；不按房名认领，不新建替代，不删除无法证明归属的频道。
- 人工角色覆盖、审计多义、权限不足或不可完整映射的访问模式继续隔离。管理员在 Discord 修正实际状态后，再刷新目录核验。
- 新鲜 REST 404 可以证明频道已被人工删除，结束登记并释放房主名额；Gateway 没看到频道或成员不算删除／空房证明。

## 由机主执行的上线步骤

延续 [v6 HANDOFF §6](../redesign-v6/HANDOFF.md#6-部署提醒) 的机主部署流程；以下是新增事项，代理未执行。

1. 备份 PostgreSQL 并确认可恢复。升级会新增 `server/migrations/0012_community.sql` 的 11 张社区表；迁移可重复运行，不删除原约局表、历史记录或语音证据。
2. 使用同一新镜像部署 app、bot 与 compose 的 migrate。保持单个 Bot Gateway 实例。
3. Developer Portal 打开 **Server Members Intent**。不需要 Message Content 或 Presence Intent。
4. 按功能授予 Bot：View Channel、Connect、Send Messages、Manage Channels、Manage Roles（频道覆盖／自选身份）、Move Members、View Audit Log；面板读取／编辑自身消息也需要相应频道访问。将 Bot 角色放在允许自选身份之上，不授予 Administrator。
5. app 与 bot 同时设 `COMMUNITY_ENABLED=true`，两端使用同一 `GUILD_ID`。Bot Token 仍只给 bot；API 不需要它。关闭开关会隐藏模块，**不会删除社区数据或已有 Discord 房间**。若要正常回收房间，先在网页暂停新建，让 Bot 完成管理后再关闭进程开关。
6. app 与 bot 保留相同 `AI_CONFIG_MASTER_KEY`、提供商配置与 `RESET_TZ_OFFSET`；密钥不要写入仓库、前端或日志。
7. 在网页选择分类／建房入口／独立等候区／公开欢迎频道与安全身份，保存并等待已应用版本追上已保存版本，再开放。
8. 按下面的真实验收清单验证。旧 Worker/D1 不应用此 PG 迁移，社区接口返回 404、网页隐藏入口；原信誉业务保持兼容。

回退时先暂停新操作，再关闭 `COMMUNITY_ENABLED` 或回退镜像；保留新表和房间登记供恢复。不要通过删表解除待对账或删除无法证明归属的频道。

## 真实 Discord 验收（待机主）

- 未绑定成员可建房、管房、选身份、玩工具；网页则要求绑定且在服务器内。
- 两端同时建房只有一间；离开建房入口后不被迟到请求拉回。
- 公开／锁门／隐藏，允许与禁止，旧房主按钮失效，转让接受与离开后认领符合规则。
- 有人重入／Gateway 断线不误删；管理员移动有一人失败就保留房间。
- 重启找回唯一建房审计；人为移动／删除、缺权限及不完整审计得到正确隔离状态。
- 欢迎零提及、24 小时默认去重；离服或过期事件不补欢迎；原绑定私信偏好不变。
- 自选安全身份多选／退出，层级与权限变更后拒绝新增，不移除管理员原有角色。
- 跨端改票、明确选人分队、不放回抽签及旧结果、骰子和标签题库。
- AI 只在主动请求时调用，5／50 默认配额，服务异常备用建议，确认前不改名。
- 换绑、撤管理员、私房访问撤销后旧结果不可见；网页选择器／错误／URL 无原始 Discord 标识。
- 原语音证据仍显示真实覆盖，社区操作不修改证据数据。

参考 Discord 官方文档：[Gateway intents](https://docs.discord.com/developers/events/gateway#gateway-intents)、[Guild channel / member / role APIs](https://docs.discord.com/developers/resources/guild)。
