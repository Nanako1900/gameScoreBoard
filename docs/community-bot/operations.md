## 成员入口

- Discord：进入指定建房语音入口，Bot 自动建房并移入；已有房间时返回原房。新房的内嵌文字聊天里是一张自动更新的控制卡，提供修改名称、人数上限、访问方式、更多操作。`/room` 为本人房间的备用入口，无房间时显示自动建房指引。
- `/roles`：多选兴趣身份，取消选中即可退出。超过 25 个候选时分页，其他页的选择会保留。
- 旧全局面板保持可选，仅保留房间和身份入口；各自打开个人私密界面，不要求配置全局面板才能管房。
- 网页首页 → **社区中心**，或 `/community`、`/community/roles`。旧 `/community/play` 显示下线说明和这两个入口，不读取历史结果。网页成员操作需登录 Nanako、绑定自己的 Discord 且仍在服务器内；Discord 内房间／身份使用无需绑定。Nanako 管理员无需绑定也可配置社区和管理已有房间。
- 全局主导航 → **设置** (`/settings` 默认个人资料) 集中名字、身份、绑定与私信偏好；成员与 AI 管理沿用 `/settings/members`、`/settings/ai`。头像菜单只保留「我的记录」「退出登录」。首次入户仍走 `/welcome`，所有旧深链保留原行为，裁判工具仍从案件页进入。

成员日常无需网页或全局控制台，直接进入建房语音入口即可；房间旁的聊天气泡可打开控制卡。网页只显示本人相关房间及折叠的辅助管理，管理员可管理全部受管房间。旧 API 创建／加入仍兼容，Bot 不会替离线成员开始语音；等待过程中位置改变时，不会用旧请求把人拉回。

每人最多创建一间临时房。默认公开可加入；能查看该临时房的当前服务器成员均可使用控制卡，锁门／隐藏、改名、人数、允许／禁止成员、移出和转让等均开放。Bot／工作人员保护仍保留。转让需对方接受，对方必须已经能查看房间，邀请 5 分钟失效；创建者离开 120 秒后，房内成员可主动认领。

临时空房默认 120 秒回收；有人重入、快照不完整或 Gateway 断线时不删除。恢复后重新观察宽限，不把离线时段推断为一直空房。直接解散仅允许空房；关闭有人临时房必须二次确认，先将所有人移往配置的等候语音频道，任一步失败都保留房间。固定房不自动回收，也不提供删除、转让或认领功能。

共享房卡对有频道查看权限的人可见，不限当前语音成员。共享卡的“更多／访问方式”打开一张私密卡；随后导航、成员选择、确认、操作状态刷新在这张卡内更新。共享卡直接打开的改名／人数表单，成功只更新共享房间状态，失败私密提示；仍排队时最多一张可刷新的私密进度卡。私密界面里的成功结果回读实际房间或身份，不把排队误报为完成。入服欢迎仍是每次有效事件的一条独立通知。

## 固定私人房间

管理员在「设置 → 社区管理 → 固定房间控制卡」选择已有私人房分类，保存并等待机器人同步。分类内已有语音房会自动登记和补卡，创建入口／等候区和已登记临时房会排除；多个固定房无需逐个发送消息。

展开对应固定房，在「房间管理员 Discord 用户 ID」填完整名单，支持换行或逗号，最多 20 人。提交会替换名单并立即清空输入；留空清空名单须再确认。机器人验证成员仍在服务器内并能查看该房间后生效；页面只显示姓名，不回填 ID。固定房管理者在 Discord 使用不要求绑定 Nanako，网页辅助管理仍要求登录和本人绑定；Nanako 管理员可以管理所有登记房间。

分配管理者不会修改 Discord 的查看／连接权限。固定房原有角色权限保留，成员网页和操作回执按真实可见范围过滤。移除分类或把频道移出所选分类会停止控制，保留真实频道与历史；重新选择后保留原管理者配置。

房间访问模式不改变既有语音记录规则：真实移动仍由原记录器记录，隐私、覆盖、保留期与查看权限不变。

## 集中管理

Nanako 管理员从 **设置 → 社区管理** (`/settings/community`，兼容 `/admin/community`) 配置：

1. 总开关；房间默认展开自助房开关、创建入口、临时房分类、空房删除分钟、默认人数五项。等候区、旧全局入口和其余策略放在「高级房间设置」。运行／版本／日志折叠，待核对操作提醒常显。
2. 公开入服欢迎频道、模板、预览和重入冷却（默认 24 小时）。只有新入服事件触发，不补发给启动时的全体成员；零自动提及、零额外入服私信。既有绑定欢迎私信独立保留。
3. 自选身份安全白名单，每人上限 1–5；托管、高权限、机器人层级以上的角色不会开放。只移除本模块赋予的身份，不接管管理员原有分配。暂停或撤白名单后仍可退出；角色本身变成高权限时，需管理员在 Discord 处理，Bot 不擅自删除。
4. 已保存／已应用版本、Bot 同步状态、资源目录刷新、面板刷新、操作记录和审计。旧趣味任务只显示安全历史状态，不重新显示原结果。

旧趣味工具、题库与社区AI配置不再显示。量刑AI及其模型密钥配置继续在 **设置 → AI 模型与密钥** (`/settings/ai`，兼容 `/admin/ai`) 管理。

开关暂停新建／新领，已有房间仍可安全管理，已选身份仍可退出。裁判没有新增社区管理员权限。只读模式拒绝提交与执行社区修改。

设置按组展开，保存栏列出已修改的分组；一次保存仍提交全部配置。校验失败会列出具体字段和要求，点击问题可展开并定位字段；保存失败保留修改。数字清空保持为空，需补全后保存，不会自动改成0。操作／审计记录加载失败可单独重试，不影响已授权的设置编辑；权限失效仍立即清除页面私密内容。

若出现「社区设置格式或范围无效」，先查看新的字段提示。本地已复现一种版本不一致情况：新网页补出的空 `fixedCategoryRefs` 被旧后端严格校验拒绝；这不代表已确认线上部署版本。C6 网页按后端实际能力保存旧格式，暂不支持固定房时禁用相应配置并提示升级。非空固定房草稿不会被静默丢弃；需由机主更新 app／bot 后再保存该功能。其他范围错误应按字段提示修正，不能通过放宽校验绕过。

`202` 只是排队。网页显示排队、执行中、已执行、失败、冲突、取消和待对账；只有实际执行回执才显示完成。失去身份／权限或换账号后，旧页面数据、旧操作结果和迟到请求不会继续显示。

旧趣味命令、按钮与表单只返回下线提示，不调用模型、不入队；旧趣味API返回410。历史数据留在原表，对外不再返回旧结果。旧配置统一为禁用兼容壳，过期题库或提示词不阻断房间／欢迎／身份保存；旧客户端也不能重新开启。

## 待对账

操作执行结果不确定时，队列停止重放同范围任务。该房间会隔离，其他普通成员不会根据旧访问模式看到它。管理员先在 Discord 检查实际频道、成员位置、角色和消息，再在网页展开 **人工核对并取消旧任务**，二次确认后：

- 只将旧任务记为已人工核对、取消并解除队列阻塞，记录审计；不重放 Discord 动作。
- 欢迎按已发送计入冷却，避免立即重复欢迎。
- 不直接恢复房间。刷新服务器目录后，只有已登记频道的类型／分类／Bot 与房主访问权限、完整访问模式可重新核验时才恢复；恢复会重建实际名称、人数限制和成员 ACL。
- 建房回执丢失，只认本 Bot 的 `community-room:<operation ref>` 审计标记。完整扫描且唯一匹配才收养；不按房名认领，不新建替代，不删除无法证明归属的频道。
- 人工角色覆盖、审计多义、权限不足或不可完整映射的访问模式继续隔离。管理员在 Discord 修正实际状态后，再刷新目录核验。
- 新鲜 REST 404 可以证明频道已被人工删除，结束登记并释放房主名额；Gateway 没看到频道或成员不算删除／空房证明。

## 由机主执行的上线步骤

C7 无新增迁移、环境变量或Intent。由机主按原流程备份、停止旧Bot并升级app／bot，保持单个执行实例；本期不提供资料库问答。新Bot重新注册命令后，旧缓存命令和历史按钮仍会收到下线提示。旧排队／重试、失效租约的趣味任务安全结束；不抢占存活租约，不批量恢复已隔离房间。普通已确认改名任务仍可正常执行，历史表和迁移均保留。新网页采用旧后端可接受的合法禁用配置壳，仍应完成两端升级后验收。

C6 无新增迁移、环境变量或 Intent。由机主更新网页与 app；固定房仍需 C5 的 app／bot 支持。更新后检查普通保存、空数字错误定位、失败保留修改及记录暂不可用时的编辑；代理只执行本机验证。

C5 无新增迁移、环境变量或特权 Intent。升级 app／bot 后，在网页选择固定房分类并分配管理者。新临时房会保留 Bot 在服务器与分类均已持有的消息权限；Discord 创建频道只允许写入 Bot 在服务器持有的权限位。请在 **Bot 角色**授予查看频道、发送消息、读取历史和嵌入链接，并检查分类／频道覆盖。仅在分类额外授予而角色未持有的位不能通过代码越权写入新频道。网页房间与运行日志会显示脱敏的控制卡故障说明，便于区分缺权限和需要核对历史。

C4 无新迁移或环境变量，沿用既有社区配置。升级 app／bot 后，已有 active 受管房间也会自动补上房内卡。Bot 在这些语音房需要 **View Channel、Send Messages、Read Message History、Embed Links**；卡片不要求另建文字频道、Message Content Intent 或置顶权限。成员看卡遵守该房间原有查看权限。若卡片缺权限，房间仍可使用，修复权限后自动重试；不要为此重复建房。

房内卡持续编辑同一消息，正常变化不刷屏；约每分钟核验消息是否被删除。删除后会先查找原标记，唯一找回或证明不存在才补建。多张同标记自有卡片须管理员核对，普通成员伪造卡片不会被 Bot 接管。房间回收不依赖面板是否同步成功。

延续 [v6 HANDOFF §6](../redesign-v6/HANDOFF.md#6-部署提醒) 的机主部署流程；以下是新增事项，代理未执行。

1. 备份 PostgreSQL 并确认可恢复。升级会新增 `server/migrations/0012_community.sql` 的 11 张社区表；迁移可重复运行，不删除原约局表、历史记录或语音证据。
2. 使用同一新镜像部署 app、bot 与 compose 的 migrate。保持单个 Bot Gateway 实例。
3. Developer Portal 打开 **Server Members Intent**。不需要 Message Content 或 Presence Intent。
4. 按功能授予 Bot：View Channel、Connect、Send Messages、Manage Channels、Manage Roles（频道覆盖／自选身份）、Move Members、View Audit Log；面板读取／编辑自身消息也需要相应频道访问。将 Bot 角色放在允许自选身份之上，不授予 Administrator。
5. app 与 bot 同时设 `COMMUNITY_ENABLED=true`，两端使用同一 `GUILD_ID`。Bot Token 仍只给 bot；API 不需要它。关闭开关会隐藏模块，**不会删除社区数据或已有 Discord 房间**。若要正常回收房间，先在网页暂停新建，让 Bot 完成管理后再关闭进程开关。
6. app 与 bot 保留相同 `AI_CONFIG_MASTER_KEY`、提供商配置与 `RESET_TZ_OFFSET`；密钥不要写入仓库、前端或日志。
7. 在网页选择分类／建房入口／独立等候区／公开欢迎频道与安全身份，保存并等待已应用版本追上已保存版本，再开放。
8. 按下面的真实验收清单验证。旧 Worker/D1 不应用此 PG 迁移，社区接口返回 404、网页隐藏入口；原信誉业务保持兼容。

回退时先暂停新操作，再关闭 `COMMUNITY_ENABLED` 或回退镜像；保留新表和房间登记供恢复。不要通过删表解除待对账或删除无法证明归属的频道。

## 真实 Discord 验收（待机主）

- 未绑定成员可建房、管房、选身份；网页则要求绑定且在服务器内。
- 两端同时建房只有一间；离开建房入口后不被迟到请求拉回。
- 已有房间的人再次进入入口会回原房；转让后旧房主、已离开入口的人或待对账房间不会被错误回流。
- 房内聊天一张卡片原地更新；人数／改名／上限／模式／房主变化自动显示，个人输入和错误只给操作者看。
- Bot 角色持有必要消息权限时，新临时房保留相应权限并能发卡；角色未持有时建房不尝试复制非法位，网页明确提示缺权限；静音不触发房管，失效同步期间进入入口后会按实际位置继续建房，期间离开不会被拉回。
- 临时房普通可见成员可操作全部控制；固定房只有已分配管理者及 Nanako 管理员可控。取消分配或撤销查看权限后旧按钮／旧队列失效。
- 固定分类内自动补卡，空房保留；旧回收／解散／转让任务也不能删除固定房。角色私房不通过网页人数、互动或操作回执泄露。
- 重启、删除卡片、发送后写回失败可恢复；缺历史权限／分类被人工移动／多义历史不盲目补发。慢或失败的卡片同步不阻塞建房与空房回收。
- 公开／锁门／隐藏，允许与禁止，旧房主按钮失效，转让接受与离开后认领符合规则。
- 有人重入／Gateway 断线不误删；管理员移动有一人失败就保留房间。
- 重启找回唯一建房审计；人为移动／删除、缺权限及不完整审计得到正确隔离状态。
- 欢迎零提及、24 小时默认去重；离服或过期事件不补欢迎；原绑定私信偏好不变。
- 自选安全身份多选／退出，层级与权限变更后拒绝新增，不移除管理员原有角色。
- 私密菜单连续选择、确认、翻页与刷新更新原消息；公共卡不出现个人选择或错误。共享表单成功不另外刷成功消息，仍排队或失败可在私密卡内查看。
- 旧趣味slash、按钮、菜单、表单、网页与接口均停用；旧任务不再执行或堵住房管，历史结果不对外返回。
- 换绑、撤管理员、私房访问撤销后旧内容不可见；网页选择器／错误／URL 无原始 Discord 标识。
- 原语音证据仍显示真实覆盖，社区操作不修改证据数据。
