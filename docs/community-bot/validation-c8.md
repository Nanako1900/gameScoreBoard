## 2. 按步骤的红绿验证

每一步均先运行失败测试，再实现、运行通过后提交；后续补充边界同样先红再修复。

1. 指定任务claim：新增PG8项。无关更早任务不再截获入口；指定项不可领取时不回退，保留同scope的queued／running／needs_review、guild隔离、并发领取、过期恢复和参数验证。
2. Discord适配器：101→155项。独立读取并行；创建及移动各读本次上下文；原位置前后核验、离开不拉回、撤权不执行、写前guard、Gateway失效、POST回执严格验证。显式ACL按id／type／数值权限比较，容许次序与等价十进制格式，缺失／重复／额外／改位结果均待对账。
3. engine调度与快路径：49→80项。指定自身任务、合并tick、逐片后台任务让入口先行；完整快照仍串行、立即失效标志补上异步runtime窗口；stop收尾；仅完整成员显示映射可复用，缺失回退；新鲜实际成员／权限仍由native预检；POST前意图、move前映射、设置／租约／版本与最终guard均保留。创建意图在确定的写前失败时关闭，不占死名额；未知创建不重建。
4. 阶段观测：新增helper6项＋真实链路6项。字段白名单、随机trace、异常与异步拒绝隔离、未决Promise不等待、排队耗时、移动不确定不报成功、无入场时戳保持null。计时map仅启用观测时写入、限制1000条并在写入时清除10分钟前数据；丢失时戳不重置起点。
5. 动态基准：新增18项。0／100／400ms、普通／管理员六组预算，POST前意图／移动前登记顺序，双入口、20间无关房、离开与撤权、快照显示数据过期但实际成员已离服／成Bot、慢面板不阻塞及未知POST不重放。请求分类及轨迹输出不含原始标识。

server合计新增115项（适配54＋engine31＋基准18＋观测12），PG新增8项。独立只读复核对本次授权委托、位置检查、快照串行、回执恢复、日志隐私及诊断边界未发现剩余具体问题。

## 3. 可复现性能证据

```bash
node --import tsx scripts/benchmark-room-creation.ts --base ed05342
```

可加`--trace`查看脱敏请求分类。脚本以git show将旧版生产源提取到临时目录，finally清理，不切换工作树、不访问真实Discord。两版都使用真实CommunityEngine与真实Discord适配器、有状态假REST、即时内存store，初始为完整warm-ready成员显示映射。

| 指标 | main | C8 |
|---|---:|---:|
| 普通成员创建回执前 请求／串行波 | 18／7 | 6／2 |
| 普通成员移动回执前 请求／串行波 | 36／15 | 13／4 |
| 普通成员全任务 请求／串行波 | 41／16 | 18／5 |
| 管理员移动回执前 请求／串行波 | 35／15 | 13／4 |
| 管理员全任务 请求／串行波 | 39／16 | 17／5 |
| 每REST统一100ms，入场到移动回执 | 1500ms | 400ms |
| 每REST统一400ms，入场到移动回执 | 6000ms | 1600ms |

普通成员移入前请求减少63.9%，串行波次减少73.3%。0ms模型同时通过预算，性能断言不依赖机器墙钟。

这不是线上测速：不模拟数据库延迟、真实网络、Gateway事件传播、客户端渲染或Discord限流。尚未完成的完整目录同步仍会串行阻塞新入口，不能为了速度跳过证据完整性。两秒为机主的目标，不能宣称本次已在真实服务器达到。
