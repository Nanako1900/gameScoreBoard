# 社区功能实施计划 · 房间、欢迎、身份与趣味工具（一个 PR）

## 1. 目标与边界

本期闭环：自助创建临时语音房 → 房主与管理员在 Discord／网页操作 → 自动交接／空房回收 → 重启恢复与操作对账。

- 同一份房间状态、权限与执行器服务 Bot 和网页。
- 网页管理员可配置入口、分类、上限、冷却、默认访问模式、回收与房主交接策略。
- C1 房间、C2 欢迎／身份、C3 趣味功能只是实现模块，全部与网页联动在本 PR 完整交付。
- 不恢复约局、不改计分／申诉／语音证据、不新建泛用聊天监听或录音。

## 2. 已确认政策

1. 分期及每期开 PR 后停下的流程。
2. Nanako 登录＋Discord 绑定，以及社区管理员的来源。
3. 新房默认公开／锁门／隐藏；每人上限与空房、房主宽限／认领政策。
4. 社区模块是否 Node/PG 专属，旧 D1 404 隐藏。
5. 是否允许 ViewAuditLog，用于严格找回建房成功但未写回的结果；否则采用人工对账。
6. 有人时主动解散、转让接受及频道内文字随临时房消失等边界，在相关操作落地前写入确认后的需求。

以上选项均已答复，完整结果见需求第 11 节。房主管空房、管理员强制关闭需安全等候区，转让须接受。

## 3. 顺序与 TDD

每步先补充能失败的测试，确认失败原因后实现，验证通过再提交。
commit 格式：`<type>: <中文描述>（C1）`，不加署名。

### 第 1 步：独立模型、持久化与隐私投影

- 独立社区配置、资源引用、房间、访问名单、操作和审计数据。
- 随机 opaque refs；数据库原始 ID 不进入 DTO、错误、URL 或审计视图。
- 操作幂等键与请求摘要、乐观版本、租约、可恢复生命周期；配置 desired/applied 分开。
- 按确认后的后端边界编写可重复执行的迁移，不读写旧约局或证据表。
- 测试：迁移重复执行、唯一性与版本冲突、幂等重放、同键不同内容、DTO 无原始标识。

### 第 2 步：Discord 资源适配与恢复证明

- 新建 `RoomApi`，保留 Bot Token 仅在 Bot 进程。
- 获取配置服务器的分类、频道、角色与有权限提供的成员目录；只通过内部映射发布选择项。
- 频道创建前持久化意图；实现已确认的审计找回／人工对账策略。
- 以完整语音状态缓存计算占用；不能用关闭成员缓存下的 `channel.members.size` 推断空房。
- 权限缺失、服务器不可用、分页不完整或找回不唯一时，返回明确不可执行／待对账状态。
- 测试：假 Discord API 下的权限撤回、创建成功回执丢失、人工同名频道、资源被移动／删除、不完整快照。

### 第 3 步：房间执行器与 Bot 交互

- Gateway 房管监听独立于语音证据记录器，按人／房间串行，限制共享连接池与 REST 并发。
- 实际移动前重查本人仍在创建入口；实际回收前重查空房、归属、版本与配置。
- Bot 命令、固定控制面板、按钮／选择菜单、定时任务调用同一执行器。
- 改名、人数、锁门、隐藏、授权进入、移出、转让、认领、解散均按已确认政策和当前权限执行。
- 重连／启动对账，未知副作用先恢复，不盲目重试创建或删除。
- 测试：重复事件、同人并发建房、重入取消清理、房主失效、旧按钮、延迟任务、只读模式、Bot 重启和故障隔离。

### 第 4 步：网页控制 API

- 以现有会话确定调用者，服务端关联 Discord 身份，执行阶段再次校验当前授权。
- API 挂载独立于绑定 OAuth 是否配置，支持管理员查看配置与诊断；成员写操作按绑定策略执行。
- 配置、资源目录、房间、动作、操作状态和审计分别投影；分页有界，`private, no-store`。
- 写入操作返回任务状态，不把 202 排队当成功。提供版本冲突、失效权限、执行失败、待对账的稳定错误分类。
- 不建立公网 Bot RPC，不向 app 增配 Bot Token。
- 测试：登录／成员／房主／管理员权限、越权 404、CSRF、私房过滤、权限迟到撤回、原始标识不泄露、Node 与 D1 的已确认能力边界。

### 第 5 步：欢迎、自选身份与全部趣味领域

- 入服欢迎频道模板／预览／启停／24 小时重入冷却／投递状态，零自动 mention，不另发入服私信。
- 兴趣身份白名单、多选上限 5、退出与权限层级复查。
- 投票（可改票）、随机分队（仅选定参与者）、不放回抽签及重抽历史、骰子、可维护话题题库。
- AI 房名／主题独立开关、提示词和配额，复用加密提供商凭据；不读取聊天／案件，结果确认后才应用。
- Bot 与网页统一领域函数、权限、配置和结果；测试重复事件、跨端去重、冷却／配额、失败回退与私房可见范围。

### 第 6 步：成员网页与集中管理

- 首页仅一个社区中心入口；社区中心中提供我的房间及可见、可加入的房间。
- 房主网页和 Discord 面板提供相同操作；网页加入采用确认后的不泄露 ID 方案。
- 管理入口归「设置 → 社区管理」，包含配置、房间列表、任务进度、运行状态和审计。
- 沿用清爽总览的浅色、留白、同名导航和触摸尺寸，个人与管理操作分层。
- 当前 main 未含清爽总览：本期必要接入必须能独立运行，不能依赖其他工作树未提交代码；完整网页改版的关系在 PR 中说明。
- 展示排队、执行中、已生效、失败、冲突、待对账；保存后回读失败明确提示，不诱导重复提交。
- 清除账号／权限变化后的私密内容及迟到请求结果；保留未保存确认与普通草稿，不能保存密钥到草稿。
- 测试：完整成员／管理员流程、空／加载／失败／过期数据、不支持后端、移动端顺序、表单确认、切换账号与请求竞态。

### 第 7 步：契约、验收与回归

- 更新需求确认记录、API／数据库契约、README、权限与部署说明。
- 写清新增权限、功能开关、升级与关闭方式、备份与可重复迁移、人工对账流程。
- 为所有产品偏离和现有代码约束记录原因，不悄悄扩大功能范围。
- 本机假 Discord API 完整走通；浏览器检查桌面与 320／390px 手机布局和隐私投影。
- 运行全部八类验证并报告前后计数。涉及 Node 新入口另跑 server build。

## 4. 必须通过的故障场景

- 同人两端同时建房，最多一间；同一幂等请求重试返回同一操作。
- Discord 已创建、写回前崩溃；重启唯一找回或待人工对账，无重复、无误认人工频道。
- 清理任务到点时有人重入；不删除房间。
- Gateway／服务器快照不可用；不把所有人当离开，不清理有人房。
- 转让、离服、解绑／换绑或撤权后，旧任务／旧按钮无法继续管理。
- 只有房管失败时，语音记录器仍保持其真实覆盖；房管不修改证据时段。
- Bot 离线或无权限时，网页能说明状态，不伪造人数为零或操作成功。
- 私房在网页列表、搜索、计数、操作状态和日志中均按当前权限过滤。
