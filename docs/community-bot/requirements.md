> 2026-10-28；基于 `a943100`。状态：机主已确认本节末尾的交付、权限与默认策略；全部功能在一个 PR 交付。

> 第 11 节记录机主最终确认，本文已按确认结果收束。使用与上线验收见 [operations.md](operations.md)。

## 1. 产品边界

- 继续使用当前单服务器 Bot、Nanako 网页和 PostgreSQL，不再建立独立后台。
- 社区功能与信誉分分别管理。使用房间、领取兴趣身份和互动不要求上榜，不加减信誉分。
- 社区房管不产生约局、报名、点名、结算或旧的守约／组局加分；不恢复已下线的约局模块。
- 既有案件、申诉、私信偏好、语音证据、旧深链继续遵守原契约。
- 私房是访问范围的设置，不改变现有语音记录告知、90 天保留和裁判／管理员／本人可见规则。

## 2. 实现模块（一个 PR）

三个模块按依赖顺序实现，每个模块均包含 Bot 入口、成员网页、管理员配置、异常反馈和相应验证，最终合在一个 PR。

| 期 | 完整闭环 | 依赖 |
|---|---|---|
| C1 | 自助语音房、房主控制、自动回收／认领／恢复、网页房间和集中管理 | 共同身份、资源映射、任务与审计基础 |
| C2 | 入服欢迎、欢迎编辑与预览、自选兴趣身份、网页个人选择和管理 | C1 共用配置／权限／目录／任务 |
| C3 | 投票、随机分队、抽签、骰子、话题卡、AI 房名／主题，均有网页入口 | 共用权限、配额、结果记录与任务 |

已确认：全部模块、全部网页联动和趣味功能放在一个 PR；不因拆步骤而延后或删除功能。

## 3. 人员与权限

| 人员 | Bot | 网页 | 约束 |
|---|---|---|---|
| 未绑定服务器成员 | 可建房／管自己的房、选择身份、参与互动 | 登录后可完成绑定，再使用本人控制 | 不自动创建 Nanako 用户或上榜 |
| 已绑定成员 | 同上 | 按当前 Discord 成员资格及频道可见范围展示 | 绑定不等于拥有任意房间访问权 |
| 房主 | 管理自己当前拥有的临时房 | 我的房间相同操作 | 每次实际执行时重查房主，转让后旧按钮失效 |
| 社区管理员 | 配置／干预 Bot 管理的社区资源 | 设置中的集中管理 | 来自现有 Nanako 管理员；裁判不自动获得 |
| 信誉裁判 | 保留既有案件／证据功能 | 保留既有功能 | 社区管理不会自动增加其权限 |

已确认身份方案：沿用 Nanako 登录；网页本人控制需要绑定 Discord；Bot 内不要求绑定；现有 Nanako 管理员明确成为本项目社区管理者。
不新增独立 Discord 登录，不将当前绑定回调当成独立登录。

## 4. 网页归属

沿用已选择的清爽总览设计：浅色、四个固定主入口、集中设置，不增加一排功能导航。

- 首页增加一个「社区中心」入口，不堆满房管／欢迎／互动卡片；案件待办仍只统计既有案件任务。
- 社区中心：房间、兴趣身份、趣味互动。默认先呈现「我的房间」和可操作的内容。
- 我的房间：状态、房主、人数、访问模式、当前可执行的操作与操作结果。
- 设置 → 社区管理：概览、房间策略、欢迎、自选身份、互动配置、运行状态与操作日志。
- 管理员配置使用频道／分类／身份选择器，不要求粘贴原始 ID。
- 当前 main 尚未实现清爽总览；社区代码不能依赖其他工作树未提交内容。实际接入范围在 C1 计划中明确，原有路径仍可访问。

## 5. C1 房间需求

### 5.1 创建与加入

- 主入口：进入指定「创建房间」语音频道，Bot 建立临时语音房并移动本人。
- Bot 命令／按钮和网页提供同一套创建／我的房间能力，不维护两种所有权。
- 网页不能让尚未连接 Discord 语音的成员直接开始语音；需要说明先连接语音，实际移动前再次确认其位置。
- 每人房间上限、全服上限、创建冷却、所在分类、命名规则和默认人数限制可配置。
- 并发语音事件、重复按钮、网页双击和请求重试不得重复建房。
- 如果成员在等待期间离开创建入口，不得由旧事件将其重新拉回；新建的无人房进入正常回收流程。
- 不在网页生成包含频道 ID 的 Discord 精确跳转、mention 或头像 CDN 地址。精确跳转若必须保留，需要另定契约例外。

### 5.2 房主控制

| 操作 | 需求与边界 |
|---|---|
| 改名 | 长度与字符校验，显示名不成为权限或恢复的依据；限制频繁改名 |
| 人数限制 | 以 Discord 合法范围和管理员上限为准；不承诺会移出现有成员 |
| 锁门 | 控制后续进入权限，不自动移出现有成员 |
| 隐藏 | 单独控制普通成员的可见性；Bot 的必要查看权限始终保留 |
| 授权／撤回授权 | 只对当前服务器成员生效，不授予服务器管理权限 |
| 移出房间 | 仅针对该房间中的目标；不是踢出服务器；保护 Bot 和管理主体 |
| 转让房主 | 当前房主或管理员操作；目标资格与是否需要接受在策略中明确 |
| 解散 | 有人房间的处理与二次确认需明确；系统不得通过空房回收误删有人房 |

已确认默认策略：公开可加入；每人 1 间；空房 2 分钟回收；房主离开保留 2 分钟，随后房内成员主动认领。管理员可在网页调整默认访问模式。

### 5.3 自动管理与恢复

- 临时房单独存储，不能借用信誉用户表、约局表或 `voice_sessions` 表。
- 房管独立监听／排队；管理故障不能把语音记录器判成离线，真实移动事件仍交给原记录器。
- 启动与重连必须对账。服务器／语音快照不可用不等于空房。
- 删除前重新检查占用、管理归属及目标分类；只清理 Bot 登记且可证明归属的临时房。
- 活跃房间不按固定寿命强制删除；短暂断线使用明确宽限期。
- 管理员手动改动、移动或删除房间要进入可解释状态，不无限尝试覆盖人工操作。
- 建房 API 成功但写回数据库前崩溃，不能按房名推断或直接重复创建。
- 已确认恢复方案：预写创建意图，并通过本 Bot 的频道创建审计条目和唯一请求标记找回；需要 ViewAuditLog。无法唯一确认时进入待对账状态，停止自动重建或删除。
- 缺审计读取权限时暂停恢复，明确提示；不盲目创建替代房间。

### 5.4 网页管理员

- 查看 Bot 在线／同步状态、受管房间列表、占用、房主、访问模式、回收计划及异常。
- 修改房间策略、暂停新建、接管／转让、锁门／解锁、安排安全回收、处理待对账任务。
- 频道配置、房间操作和批量动作分别确认，记录操作者、目标、版本、结果和时间。
- 可查看配置已保存与 Bot 已应用的版本，避免把离线期间保存配置误当成已在 Discord 生效。
- 不以社区房管权限开放案件、陈述、判词或历史语音证据；这些继续走既有权限接口。

## 6. C2 欢迎与兴趣身份

### 欢迎

- 新增「加入服务器」欢迎，与现有绑定／换绑后的欢迎指南私信分别触发和配置。
- 网页可编辑模板、选择目标频道、预览实际渲染、启停，并查送达／失败状态。
- 只使用受支持占位符，限制长度和自动提及，不能让模板任意 @everyone。
- 重复入服事件、重连和启动基线同步不能引发重复或全员欢迎。
- 成员已离服、消息已过期或功能已关闭时，投递任务应跳过。
- 不提供额外入服私信，不复用或重新打开现有案件私信开关。
- 已确认：仅公开频道、无额外私信、无自动提及，默认 24 小时重入冷却，网页可配置。

### 自选身份

- Bot 按钮／选择菜单与网页操作同一份白名单；网页可显示当前拥有与待应用状态。
- 管理员配置游戏／兴趣身份白名单与多选上限。
- 不能自选管理员、Bot 托管、工作人员、信誉裁判或社区管理员资格；执行时重查角色权限和层级。
- 角色删除、层级变化或管理员将其改成高权限时，暂停发放并提示配置需复核。
- 最多 5 个，可自主退出；只移除本模块赋予的角色，原有管理员分配不受影响。

## 7. C3 趣味功能（保留）

| 功能 | Bot 与网页共用的行为 | 对应网页管理 |
|---|---|---|
| 投票 | 创建、投票、截止／关闭、结果；同一 Discord 身份跨端去重 | 可见范围、时长、选项限制、改票策略、关闭与记录 |
| 随机分队 | 明确参与者、均衡人数、生成结果 | 参与者选择、队数、结果和重抽策略 |
| 抽签 | 服务端抽取，结果不可由浏览器提交冒充 | 候选、数量、是否放回、重抽与短期历史 |
| 骰子 | 同一参数校验和服务端随机逻辑 | 骰子数量／面数限制、冷却及结果 |
| 话题卡 | 按标签从管理员题库抽取 | 题库、标签、启停和维护 |
| AI 房名／主题 | 根据主动输入生成建议，用户确认应用 | 独立开关、提示词、配额、调用结果和回退 |

- 不把互动结果接入信誉分、处罚或自动管理决策；不恢复旧约局流程。
- AI 不读取私密案件、陈述、语音证据或普通聊天正文，也不直接授予权限、移人或关闭房间。
- 可复用既有加密凭据和请求基础设施，但社区提示词、配额、日志与现有归类／量刑／战报分开。
- 改票、重抽和 5／50 默认 AI 配额均已确认，与全部工具在本 PR 交付。

## 8. 共用技术与隐私契约

### 8.1 唯一执行者

网页 → 已鉴权 API → 持久操作记录 → Bot 校验并执行 Discord 操作 → 写回结果 → 网页读取结果。

- Bot Token 只在 Bot 进程，不交给网页或 API，也不增加公网 Bot RPC。
- API 返回「排队／执行中」与实际成功分别表达；网络超时不能让用户盲目重提操作。
- 使用幂等请求键、资源版本、执行租约和受控重试；执行时重新检查成员资格、权限、房主和目标状态。
- 权限被撤销、解绑、换绑、离服或房主变更后，旧操作不得按旧身份继续执行。

### 8.2 网页资源引用

- 房间、成员、频道、分类和角色使用随机 opaque ref，服务端映射到原始 Discord 标识。
- 不使用原 ID 改字段名、Base64、可解码签名载荷或含 ID 的跳转／头像 URL 替代隐私处理。
- 下拉选项仅返回当前调用者有权查看的名称、类型、状态和可用能力；ref 本身不代表授权。
- 私房名称、成员和人数也按可见范围过滤，不能只藏链接。
- 资源目录只是选择器读模型；真实操作前仍由 Bot 重查，不把过期目录当作在线事实。

### 8.3 最小数据集合

- `community_settings`：期望配置、版本、应用状态及 Bot 状态。
- `community_resources`：原始 Discord 标识的内部映射、随机 ref、名称、类型和同步代次。
- `community_rooms`：房主、频道内部标识、创建阶段、实际状态、版本、回收／交接期限。
- `community_room_access`：允许／拒绝成员及授权来源。
- `community_operations`：操作者、幂等键、预期版本、租约、阶段、结果与恢复状态。
- `community_audit`：必要的配置及管理操作审计，公开 DTO 不含原始 ID 或底层错误详情。

这些是建议逻辑实体，实际迁移可合并字段／表，但不能丢掉授权、幂等、恢复或审计含义。

### 8.4 已确认运行边界

机主已确认采用现有 Discord 绑定的 Node/PG 专属模块方式：旧 Worker/D1 返回 404，网页隐藏入口；既有信誉业务继续保持 D1/PG 一致。

需要的权限随能力启用：频道管理、移动成员、频道权限覆盖、可能的建房审计读取；成员入服事件及完整成员目录需要相应成员事件能力。部署、权限启用、备份和远程迁移均由机主执行。

## 9. 验收重点

- 双击、并发、重启、断线和超时不重复创建；未知结果不误报成功。
- 私房不向无权限的人出现在列表／搜索／计数／日志／链接中。
- 房主／管理员两端同权，旧按钮和延迟任务不保留失效权限。
- 空房回收遇到成员重入、快照失败、权限变更或人工移动不误删。
- 创建成功未写回的恢复不能仅凭名称；不能认领或删除人工频道。
- 网页所有响应、错误、URL、头像、缓存和日志视图不泄露原始 Discord／频道／角色标识。
- 现有语音对账、覆盖、降级、90 天保留、案件隐私及永久深链回归通过。
- 每期按先失败测试、实现、通过后提交，提 PR 前跑全部八类验证并记录前后数量。

补充确认：管理员在 Discord 人工核对后可二次确认取消待对账旧任务并解除队列阻塞，只改任务记录、不重放；欢迎按已发送计冷却。房间仍须重新验证受管频道或建房审计，无法验证继续停用。

其他安全细节按不扩大权限、不误删、不泄露、不误报成功实施。
