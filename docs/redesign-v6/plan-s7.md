# S7 · 网页与 Discord 语音记录呈现

机主在 S6 合并后明确要求优化网页语音记录与 Discord `/voice` 回复。只改显示格式和入口，不改变采集、对账、覆盖、累计计算、保留期、权限或接口。

## 1. 基线

2026-10-28，最新 `origin/main` 为 `3119a96`（#43），Node 22.22.3，八项全通过：unit 44 文件 / 687，DOM 50 / 657，D1 18 / 555 + 5 todo，PG 40 / 953 + 5 todo，server 32 / 378；typecheck、build、build:pages 通过。PG 用 `env -u TEST_DATABASE_URL npm run test:pg`，仅临时本机数据库。

## 2. 展示决定

- 网页和私密回复采用同一格式：日期与累计时长、首次进入／跨日延续、频道、精确进出时间、证据说明分层显示；最近日期在前。
- 同日端点只写时钟，跨日端点补日期；所有段与缺口保留秒。累计仍直接使用 API 的 `total_min`，按天累计秒数后向下取整的算法不变；例如 `1小时5分钟`，整点不显示 `0分钟`。
- 空日缩成一行，保留全部查询日期，不把 `total_min=0` 当成没有段。整页说明“没有保存的语音记录，不代表没来”。
- 缺口数量与警告始终可见，网页用原生 details 展开完整秒级清单；不合并、不截断或重新推断覆盖。提示改成“这些时段没有完整记录”，避免将清理或心跳尾段也说成机器人离线。
- 开段保持“尚未记录离开”和估算说明；上线对账、离线结束、跨日延续说明保留。只有 API `in_voice_now=true` 才表示当前在语音。
- Discord 仍为一条 ephemeral embed。优先省略段明细，再省略完整缺口条目；保留全部日摘要及所有固定证据说明，准确标明未展开的条目数量，绝不暗示其余时间已覆盖。遵守原有全部长度预算与转义规则。
- 网页入口采用 S6 当前地址：本人到个人页，裁判／管理员到语音工具页；旧地址永久兼容，不改命令权限或 1–14 天范围。

## 3. 步骤与提交

每步先失败测试，再实现、相关验证通过后提交，格式 `<type>: <中文描述>（S7）`。

1. 共享格式：日期区间、秒级端点、首次／延续、时长与提示；验证半小时时区、跨午夜／跨年、无效输入、0分钟开段、不修改原数据。
2. 两端布局：网页按日层级与紧凑空日、缺口展开；Discord 分层内容、完整条目降级、当前网页入口。两端可并行实现，统一提交前检查所有相关套件。
3. 文档、桌面和320/390px本机虚构数据验收、全量八项验证，记录各套件前后数量后提一个PR。

## 4. 不变约束

本人、裁判、管理员以外不读取私密语音，越权仍404；不暴露Discord或频道ID；React转义、Discord safeLine 转义保持；只加可选组件props；CSP无内联style；DOM阅读顺序等于视觉顺序。D1/PG行为与全部S3证据规则不改，不增依赖、API或迁移，不操作远程服务。
