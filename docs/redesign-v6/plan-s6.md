# S6 实施计划 · 清爽总览与集中设置（一个 PR）

> 2026-10-28，机主在完成 S1–S5 和 #42 后，选择「清爽总览」并确认完整设计稿，随后授权开始实现。
> 本期替换 spec §3 的网页布局和入口安排；spec §2、§5 的证据规则、§8 的隐私和兼容约束继续有效。
> 全部业务表单沿用当前 main 的契约；不实施 HANDOFF §5 仍待拍板的业务功能。

## 1. 目标

- 浅色黑白、克制强调色、清楚标题与留白，取消深色电竞、发光、段位装饰和相同权重卡片堆叠。
- 所有宽度只有一套主导航，名称和 DOM 顺序固定为「首页／信誉榜／案件／设置」。头像只提供我的记录与退出。
- 首页只放入户缺项提示、我的分数与待办摘要、最近三条判决和一行战报入口；不再重复完整榜单。
- 日常设置集中，首次入户保持独立。个人与案件详情统一整页，业务操作保留现有权限和校验。

## 3. 页面和兼容

- `/`：清爽总览。
- `/board`：完整信誉榜；不再把案件、战报、规则混在榜单的主标签里。
- `/cases`：我的待办与公开记录，保留全部历史状态的入口；`/cases/:id` 与 `/players/:id/cases/:id` 保留。
- `/settings`、`/settings/profile`、`/settings/discord`：日常个人设置；管理员追加 `/settings/members`、`/settings/ai`。
- `/tools`：裁判/管理员工具；`/tools/filing`、`/tools/voice`、`/tools/score` 复用原有表单和证据组件，人工调分只给管理员。
- `/players/:id`：完整个人记录页；段位只本人可见，其他人使用中性分数与走势。
- `/welcome`、`/guide`、`/board/report`、`/board/rules` 保留。帮助入口放页脚，战报入口放首页一行。
- `/board/feed` 显示案件内容，旧 `/admin/ai`、`/admin/members` 进入新设置布局，旧 `/admin/voice?user=...` 进入新工具布局；原权限、查询参数和 404 行为不变。
- `?case`、`?session`、`?linked`、`?onboarding` 永久兼容；入户完成先回首页再继续原目标；已有登录回跳、草稿、返回层栈继续工作。

## 4. 实施步骤

每步先写能证明缺失行为的失败测试，再实现，相关套件通过后 commit。提交格式 `<type>: <中文描述>（S6）`。

### 第 1 步 · 四项导航与整页路由

新增 settings、cases、tools 路由与共享导航模型；保留旧地址。Header 在所有宽度渲染四项，App 停止渲染第二套底栏。头像菜单精简；已有可选回调签名保留。个人和案件页面覆盖首页，不再作为桌面抽屉。

验证新路径解析/格式化、未知路径和保留前缀、导航 active、同名同序、单次案件 lookup、主客体纠正、查询串保留、旧深链和返回。

### 第 2 步 · 集中设置与未保存保护

设置页复用 IdentityForm、DiscordLinkCard、AiSettings、MemberList。抽取可复用 Discord 通知区块供入户与设置共享，保留绑定、私信开关、重发欢迎私信限制与 404 静默隐藏。

身份编辑保留 Nanako 名字来源和 24 字上限。AI 的连接/凭据优先，高级提示词和原有四项统计折叠。密码不回填、不进草稿，清密钥时保存其他配置的语义不变。普通表单独立保存，有未保存内容时给离开确认；账号和权限变化立即撤下旧内容，旧请求不得污染新账号。

验证普通成员只见个人两组，管理员才见 AI 和成员；裁判或越权旧管理地址仍 404。验证保存、失败、成功写入后刷新失败、路由离开确认、回跳与密码清理。

### 第 3 步 · 首页总览与案件列表

首页分数在前、待办摘要在后，按 DOM 顺序响应式重排；不上榜不展示虚构分数。无待办只显示一行；入户提示不计数，管理员申诉按案件数计。

最近判决固定三条，不在首页展开更多；完整历史在案件页。完整 TodoInbox 移到案件「我的待办」，公开记录保留申诉、撤案、撤销和历史加分。首页战报缩成一行，规则和指南在页脚。

验证首页主次、无迷你榜、三条判决、待办计数与未知/失败不冒充零、访客和不上榜、公开记录权限与历史状态。

### 第 4 步 · 个人、案件与裁判工具

复用现有 PlayerDetail、CaseActions、CaseDialog、VoiceLog、AdminScoreForm。案件整页突出当前案件，其他历史不重复堆在案件正文。个人页保留走势和个人语音，管理动作跳到统一工作位置。

移除他人段位名称、描述和颜色传播。立案排除本人，事实至少 10 字、个人补充最多 300 字，部分成功只重试失败人。陈述提交后立即进入裁决、不可再改；申诉可空理由且保留确认；升级、改判、撤案、撤销、15 分钟原立案人撤销窗口全部按现有规则。语音按成员查范围、按日查单日，保留缺口、跨日、不确定离开与 90 天保留期。

验证对象上下文、角色、异步旧请求、操作确认、部分成功、草稿返回、他人段位不可见、语音越权 404 和不误报已覆盖。

### 第 5 步 · 浅色视觉和可访问性

统一 theme 语义色、字号、间距、边框、按钮、焦点；移除暗色硬编码、渐变发光和内联 style，改用 CSS 类和 SVG 属性。正文/输入 16px、说明 14px、时间 12px；触摸目标至少 44px。

重排首页、榜单、详情、设置、证据、弹层；DOM 顺序就是视觉顺序。头像、仪表和图表保持组件可选 props 兼容，不再通过内联颜色泄露段位。

验证对比度、CSP/源码卫生、公开段位中性、页面语义、键盘/焦点、加载/错误/旧数据；本机检查桌面和 320/390px 窄屏。

### 第 6 步 · 文档与最终回归

更新 README、CONTRACT、spec §3 与 HANDOFF 进度，使路由、导航、设置和权限说明与最终实现一致；记录原型与代码的必要偏离及原因。

对照本计划补齐契约检查；跑第 6 节全量验证，记录前后测试数，人工检查真实渲染后提 PR。

## 5. 不变的约束

- 判前按接口脱敏；已判决不等于可公开全部正文；段位只本人可见。
- 网页不输出 Discord ID、频道 ID、邮箱或密钥；本人绑定昵称沿用已确认的 GET 契约。
- 语音只本人、裁判、管理员可见；越权返回 404；只认可信覆盖。
- CSP 不写内联 style、内联 style 标签或 dangerouslySetInnerHTML；已有组件只加可选 props。
- D1 / PG 行为一致；不删历史表和数据，不改远程数据库。
