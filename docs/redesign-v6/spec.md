# v6 方案 · Discord 为主，网页做减法

> 2026-10-27 定稿，机主已确认本文的设计和第 2 节的全部决定。
> 本文取代 v5（`docs/redesign-v5/spec.md`）里所有和约局有关的设计。v5 中与约局无关的规则继续有效：判决前脱敏、段位只给本人看、CSP、深链兼容、锁定文案（第 8 节列出解除锁定的几条）。
> 实施计划：[plan-s1.md](plan-s1.md)–[plan-s5.md](plan-s5.md)。进度与交接：[HANDOFF.md](HANDOFF.md)。

## 0. 结论

- **Discord 是日常入口。** 约局整个下线（网页和机器人都删）。迟到、放鸽子改由裁判手动记一笔，机器人记录的语音进出时间作为证据。
- **网页只做三件事：**
  1. 带新人走完入户：登录 → 加入服务器并绑定 Discord → 开私信 → 名字与身份 → 机器人指南；
  2. 让人查看榜单和最近的案件；
  3. 给裁判和管理员做管理。
- **机器人新增三样：**
  1. 记录已绑定玩家进出语音频道的时间；
  2. 在一个专用文字频道里维护一条「信息板」消息，内容变化时原地编辑；
  3. 发欢迎私信，提供 `/help` 和 `/voice` 两个命令。
- **分 5 期，一期一个 PR：** S1 约局下线 → S2 入户 → S3 语音记录 → S4 信息板 → S5 管理页。

## 1. 为什么改

P3 上线后，网页的页面和入口越来越多，越做越难用。成员实际都在 Discord 里活动，Discord 才是最方便的入口。所以网页做减法：只留新人入户、看排名和案件、管理三件事，其余交给机器人。

## 2. 已拍板的决定

| # | 问题 | 决定 |
|---|---|---|
| 1 | 约局怎么处理 | **整个砍掉**：网页和机器人里的约局全部删除。迟到、放鸽子由裁判手动记一笔；守约 +2、组局 +2 不再产生。 |
| 2 | 「进入时间」指什么 | **进出语音频道**。只记已绑定的人。 |
| 3 | 进出记录谁能看 | **裁判、管理员和本人**。 |
| 4 | 网页上还能不能写说明、提申诉 | **保留，作为备用**。案件页现有按钮不动。 |
| 5 | 进出记录保留多久 | **90 天**，到期自动删除。天数是 `shared/voice.ts` 里的常量 `VOICE_RETENTION_DAYS`：机器人和 API 分属不同容器，用常量避免两边配置不一致。 |
| 6 | 能不能选择不被记录 | 不能。入户和 `/help` 里写明；解绑后停止记录。 |
| 7 | v5 的 P4、P5 | 作废。其中仍有价值的几项放进 HANDOFF「后续待办」，要做再拍板。 |

## 3. 网页

S6 按机主确认的「清爽总览」设计更新网页布局与入口。本节取代 S1–S5 实施时的网页排布，不改变第 2 节的决定、语音证据规则或第 8 节的约束。

### 3.1 路由

| 地址 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 清爽总览，见 3.3 |
| `/board` | 信誉榜 | 完整榜单，不再混放动态、战报、规则标签 |
| `/cases` | 案件 | 「我的待办」「公开记录」；`?view=public` 直接打开公开记录 |
| `/settings`、`/settings/profile`、`/settings/discord` | 设置 | 个人资料、Discord 与通知；`/settings` 等于个人资料 |
| `/settings/members`、`/settings/ai` | 管理员设置 | 成员与权限、AI 模型与密钥，见 3.4 |
| `/tools`、`/tools/filing`、`/tools/voice`、`/tools/score` | 裁判工具 | 工具首页、记一笔、语音记录、人工调分，见 3.4 |
| `/welcome` | 入户 | 独立的首次入户清单，见 3.2 |
| `/guide` | 机器人指南 | 和入户第 5 步、机器人 `/help` 共用同一份文案 |
| `/board/report`、`/board/rules` | 战报、规则 | 保留；规则只列扣分类型，不含约局内容 |
| `/players/:id` | 个人记录 | 分数、走势和案件；本人另有个人语音记录 |
| `/players/:id/cases/:caseId`、`/cases/:id` | 案件详情 | 聚焦当前案件；后者查出当事人后替换为前者，查询参数保留 |
| `/board/feed`、`/admin`、`/admin/voice`、`/admin/ai`、`/admin/members` | 旧地址 | 保留，显示新的案件、工具或设置布局，见 3.5 |
| `/sessions`，以及它下面的所有地址 | 「约局功能已下线」 | 旧链接的落地页，见 3.5 |
| 其他 | 「这页不存在」 | 不变 |

- 桌面和手机只有一套主导航，名称、DOM 和视觉顺序固定为「首页／信誉榜／案件／设置」。已知待办数量显示在「案件」上，入户提示不计数；不再另设底部标签栏。
- 头像菜单只保留「我的记录」「退出登录」。规则、机器人指南和入户向导放在页脚；裁判与管理员从案件页进入裁判工具。
- 导航目的地、个人记录和案件详情在所有宽度都使用整页，不再使用桌面抽屉。真正的编辑、陈述和确认对话仍保留其焦点与返回行为。
- 路由仍然只看 pathname，查询串和 hash 不参与选路由（P1 的规则）；查询参数只选择页面内部视图或对象。
- 视觉采用浅色底、黑白层次、细边框与克制的强调色，取消深色电竞、渐变和发光。所有分数、仪表、徽章与走势不使用段位配色；本人仍能看到自己的段位名称和说明。

### 3.2 入户 `/welcome`

一页纵向清单，共五步，每步一张卡。

- 每步是否完成都从服务器读，不靠浏览器存储。
- 已完成的步骤打勾并折叠，第一个没完成的步骤展开。
- 入户与日常设置分开：已有成员修改资料或通知，去 `/settings/profile`、`/settings/discord`；`/welcome` 保留完整清单，不再充当设置页。

| 步 | 标题 | 完成条件 | 内容 |
|---|---|---|---|
| 1 | 登录 | `me.user` 不为空 | 「用 Nanako 账号登录」，登录后回到 `/welcome` |
| 2 | 加入服务器并绑定 Discord | `GET /api/me/discord` 的 `link` 不为空 | 先给「加入服务器」按钮（`VITE_DISCORD_INVITE_URL`），再给「绑定 Discord」按钮（现有 `/link/discord` 流程） |
| 3 | 开启私信通知 | `notify_dm` 为开，且 `dm_ok` 为真（两项 `GET /api/me/discord` 已经返回） | 私信开关；送达提示（见下）；「再发一次」 |
| 4 | 名字与身份 | `is_participant` 或 `is_judge` 至少一个为真 | 把现在 `OnboardingDialog` 的显示名和身份两块原样搬过来，裁判身份仍然只能由管理员授予 |
| 5 | 机器人怎么用 | 无（看过即可） | 指南正文（共用文案）、语音记录告知、「完成，去首页」 |

**欢迎私信：**
- 绑定成功（新绑或换绑）时，机器人发一条私信，内容是指南、信息板频道和网页地址。
- 第 3 步不追踪单条私信，只看现有的 `dm_ok`（机器人私信失败时会把它置 0）：
  - `dm_ok` 为真：「已开启。没收到欢迎私信？点「再发一次」」；
  - `dm_ok` 为假：「上次私信没送到。请确认：① 已经加入服务器；② 隐私设置里允许服务器成员私信你。改好后点「再发一次」」。
- 「再发一次」每人 24 小时内最多 3 次，只算手动重发。点了以后提示「已让机器人再发一次，去 Discord 看看；没收到就刷新本页看原因」。
- 私信开关关闭时，不发欢迎私信，也不显示「再发一次」。

**什么时候带人来这里：**
- 首次登录（`?onboarding=1`）直接进 `/welcome`。
- 绑定回跳（`?linked=discord`）也进 `/welcome`，同时显示现有的「Discord 绑定成功」提示。
- 首页上，已登录但第 2、3、4 步还没做完的人，会在分数与待办摘要之前看到「还差 N 步完成入户」提示和「继续入户」入口。它不计入待办数量，也不重复放进案件待办。
- 完成入户先回首页，再自动继续原来的 `?case`、`?session` 或登录回跳目标；绑定流程保留原目标，不能丢失深链。
- Discord 读取中或普通错误不算完成。后端不支持绑定、私信接口时仍要求完成这两步，暂不允许完成入户；不把 404 当成已完成。

`OnboardingDialog` 弹窗退役。

### 3.3 首页与查看

首页的 DOM 顺序（也就是视觉顺序）：

1. 问候、简介和完整信誉榜入口。
2. 已登录且有缺项时显示入户提示。
3. 已登录：我的分数在前、待办摘要在后。桌面可并列，手机按同一 DOM 顺序纵向排列；不上榜的人显示「当前不上榜」，不展示虚构分数或排名。未登录：欢迎卡和入户入口。
4. 最近判决：复用 `RecordsFeed`，固定最多三条已判决或申诉中的扣分记录，不含判前隐藏记录或历史加分；行入口打开该案件。「全部案件」指向 `/cases?view=public`，首页不展开更多。
5. 一行战报入口：周期和「阅读战报」；没有战报时说明暂无，不堆放战报正文。

首页不再重复迷你榜单、完整待办、规则和战报卡片。没有待办只显示一行「当前没有待办」；读取中或失败不能冒充零。管理员的待复核申诉按案件数计入摘要与导航数量。

**案件与个人记录：**

- `/cases` 对已登录者默认显示「我的待办」，访客默认显示「公开记录」。完整案件待办保留陈述、升级确认和管理员申诉复核入口。
- 公开记录保留处理中、已判决、申诉中、已撤案、已撤销及历史加分的筛选。只筛选当前接口已读取的记录，不声称显示完整数据库；`redacted`、`pending_hidden` 不能被摘要、状态筛选或行入口绕开。
- 个人记录页保留分数、走势、案件历史；只有本人能看到自己的段位名称与说明，所有人的分数和走势视觉均为中性。
- 个人语音只在本人记录页内读取。裁判、管理员查看他人时提供对应的语音工具链接，不在公开个人页嵌入他人证据。
- 案件详情突出当事人、当前案件和现有授权操作，不重复堆放个人分数、走势、语音与其他案件。陈述、申诉、升级、改判、撤案、撤销继续遵守现有校验与权限。

### 3.4 集中设置与裁判工具

**设置：** 普通成员只有个人设置，管理员追加管理员设置。不是管理员的人直接访问成员或 AI 设置（包括旧地址）仍返回「这页不存在」，挂载表单前就拦下，不读取私密配置。

| 分类 | 谁能看到 | 内容 |
|---|---|---|
| 个人资料 `/settings/profile` | 已登录者 | 显示名与身份，保留 Nanako 名字来源、24 字限制；裁判身份仍由管理员授予 |
| Discord 与通知 `/settings/discord` | 已登录且后端支持 | 绑定、解绑、私信开关、送达状态与重发欢迎私信；沿用原限制和本人绑定昵称契约 |
| 成员与权限 `/settings/members` | 管理员 | 全部账号，包括不上榜的；设/撤裁判，人工调分链接进入统一工具 |
| AI 模型与密钥 `/settings/ai` | 管理员 | 连接、模型和凭据在前；Temperature 与三类提示词折叠在同一「高级参数与提示词」，原四项运行统计独立折叠 |

- 表单分别保存；有未保存修改时离开需确认。密码不回填、不进草稿，请求后或卸载时清空；清密钥仍同时保存其他配置。写入成功但回读失败要明确已保存，不能误报为未提交。
- 账号或权限改变立即撤下旧内容，旧请求不能污染新账号；接口 403/404 不暴露后端私密说明，Discord 不支持时静默隐藏对应设置入口。

**裁判工具：** `/tools` 汇总「记一笔」「语音记录」；管理员另有申诉复核入口和人工调分。普通成员和访客直接访问工具地址显示「这页不存在」。

- `/tools/filing` 复用立案表单与已有草稿、部分成功处理；选择当事人后，语音入口指向 `/tools/voice?user=<id>`。
- `/tools/voice` 默认按榜单时区展示当天汇总；`?user=<id>` 查看成员最近 7 天、最长 31 天的分日明细。保留跨日、保留期、不确定离开和未覆盖提示，不能以打开的语音段代替可信覆盖。
- `/tools/score` 只给管理员，先选择账号（包括不上榜的），再确认新分数；`?user=<id>` 可直接打开对应账号，成员设置和个人页复用这个位置。
- 改判、撤销、升级保留在案件上下文；重新生成战报保留在战报页。没有新增「每案只能申诉一次」等尚未实施的业务限制。

### 3.5 旧地址

- `/board/feed` 是公开案件记录的兼容入口，使用新案件布局；不再维护第二套动态页。
- `/admin`、`/admin/voice` 进入新的语音工具布局，`?user=<id>` 保留；旧地址仍只给裁判和管理员。
- `/admin/ai`、`/admin/members` 进入新的集中设置布局，仍只给管理员，不保留旧管理三标签布局。
- `/sessions`、`/sessions/:id`、`/sessions/new`、`/sessions/history`、`/sessions/:id/rollcall`：显示「约局功能已下线」页，正文是「约人直接在 Discord 里喊；迟到、放鸽子由裁判记录。」，按钮「回首页」。
- `?session=N`：永久深链，不报错。落到首页，弹一条提示：「约局功能已下线」。
- `?case` 永久兼容，打开对应案件；`?linked=discord`、`?onboarding=1` 仍按 3.2 进入入户，完成后继续原目标。
- 登录回跳保留「回到原来的页面」，设置中发起绑定也保留原设置目标。旧版本存下的「报名」意图，读到时直接忽略。
- 保留已有草稿、返回键与焦点恢复，不因整页布局或旧地址换壳丢失原目标。

### 4.4 intent 与权限

- S3 起 intents 是 `Guilds` 加 `GuildVoiceStates`。后者不是特权 intent，不用去开发者后台申请。语音状态的缓存要打开，否则启动时没法对账。
- 邀请权限不变（`permissions=19456`：查看频道、发消息、嵌入链接）。信息板频道请机主设成成员只读，机器人保留查看和发言权限。

## 5. 语音进出记录（S3）

**记什么：**
- 已绑定的人，每进一次语音频道记一段：进入时间、离开时间、频道 id、当时的频道名。
- 换频道算作上一段结束（`moved`）、新的一段开始（`moved`）。
- 静音、开关摄像头这类变化不记。
- 未绑定的人不开新段。但「离开」一律照关：不管现在是否绑定，只要这个 Discord 账号还有开着的段，就把它关掉。
- 机器人只能看到它有「查看频道」权限的语音频道。机主要保证机器人能看见所有需要留证的语音频道。

**数据**（D1 和 PG 两边建同样的表，时间都用 UTC 文本 `YYYY-MM-DD HH:MM:SS`，和 `records.created_at` 一样）：

```
voice_sessions
  id               自增主键
  user_id          text, 引用 users(id)，删用户时一起删
  discord_user_id  text
  channel_id       text
  channel_name     text
  joined_at        text
  left_at          text, 可空（为空表示还在语音里）
  start_reason     'joined' | 'moved' | 'bot_online'
  end_reason       'left' | 'moved' | 'bot_offline' | 'unlinked'，可空
  索引：(user_id, joined_at)
  唯一：同一个 discord_user_id 最多一条 left_at 为空的记录

voice_coverage                       -- 机器人在线、能看到语音事件的时段
  id               自增主键
  started_at       text
  last_seen_at     text              -- 机器人在线时每 60 秒更新一次
```

**对账（保证证据可信）：** 机器人每次拿到服务器的完整状态时都要对账一次，包括启动和断线后重新建立会话。discord.js 每次重新识别都会对本服务器触发 `GuildAvailable`，只在这个事件上对账，并且一次只跑一个。

1. 关掉所有「数据库里还开着、实际已经不在语音里」的段：`left_at` 取 `max(joined_at, 上一个覆盖时段的 last_seen_at)`，`end_reason = 'bot_offline'`。
2. 给「实际在语音里、数据库里没开着」的已绑定的人开一段：`joined_at` 取现在，`start_reason = 'bot_online'`。
3. 新开一个覆盖时段。

**覆盖时段只记真正看到了的时间：**
- 短暂断线后恢复（`ShardResume`）：静默不超过 2 次心跳（120 秒），沿用原来的覆盖时段，Discord 会补发事件；超过 120 秒，结束当前覆盖时段，从恢复时刻开新的，中间那段就成了未覆盖时段。补发事件的时间按处理时刻记，所以只是近似值。
- 记录器写库失败：停止心跳，当前覆盖时段到此为止；数据库恢复后先完整对账，再开新的覆盖时段。不能出现「显示已覆盖、其实没写进去」的情况。

**显示：**
- 按榜单时区（`RESET_TZ_OFFSET`）分日。查询按时间重叠选段：段的开始早于范围结束，并且（离开时间，或者还开着时的现在）晚于范围开始，就算在范围内。
- 每天显示首次进入时间（当天开始的段里最早的一段；当天只有从前一天延续过来的段时为空）、累计时长（跨午夜的段按天切开计算）和每一段的明细。
- 跨午夜的段在第二天也列出来，标注「接上一天」。
- `bot_online` 开始的段写「机器人上线时已在语音里」。`bot_offline` 结束的段写「之后机器人离线，离开时间不确定」。
- 查询范围里如果有不在覆盖时段内的部分，单独列出来，并写：「这段时间机器人不在线，没有记录不代表没来。」

**接口与权限：**
- `GET /api/voice?user=<id>&from=YYYY-MM-DD&to=YYYY-MM-DD`
  - 需要登录。`user` 是自己时任何人都能查；查别人要是裁判或管理员，否则返回 404。
  - 范围最多 31 天。
  - 返回分日结果加未覆盖时段，不包含任何 `discord_*` 字段。时间格式和 `records` 一样，用 UTC 文本 `YYYY-MM-DD HH:MM:SS`。
- `GET /api/voice/day?date=YYYY-MM-DD`：只给裁判和管理员，返回这一天每个人的首次进入时间和累计时长。

**保留与解绑：**
- 机器人每小时清理一次：删掉 `joined_at` 早于 `VOICE_RETENTION_DAYS`（90）天的段（开着的也删），以及 `last_seen_at` 早于这个时间的覆盖时段。
- 解绑或换绑时，旧 Discord 账号还开着的段以 `unlinked` 结束，之后不再记录这个账号。

## 6. 信息板（S4）

**放在哪：**
- 配置 `DISCORD_BOARD_CHANNEL_ID`。不填就不发信息板。
- 机器人在这个频道里只维护一条消息，存在 `discord_messages`，主键是 `('board', 'main', 'board')`。

**消息内容**（一条消息，最多 3 个 embed）：

1. **信誉榜**：上榜选手前 15 名，每行「名次. 名字 — 分数」。不显示段位，段位只给本人看。不用 @ 提及，不出现任何 Discord 账号信息。
2. **最近判决**：最近 5 起已判决的扣分案件（不算历史上的 +2 加分）。字段和排序与 `/verdicts` 相同，每条附网页链接（`webUrl` 生成的 `?case=<id>` 深链），时间用 `<t:秒:R>`。
3. **动态**：
   - 「目前有 N 起记录在处理中」：判决前的案件（`awaiting_statement`、`judging`）只给数量，不写人名，和 B1-1 一致；
   - 最新一期战报的一句话摘要加链接；
   - 「更新于 <t:秒:R>」。

按钮放在一行：「我的情况」「语音记录」「打开网页」。

**什么时候更新：**
- **触发：** 下列表变化时，PG 触发器排一个 outbox 事件 `board.refresh`。第一次变化把事件排在 10 秒后；执行前又有变化，就并进同一个事件，执行时间不往后推（`outbox_schedule` 的 coalesce 模式），所以连续不断的变化也不会把更新一直拖住。
  - `score_events` 新增；
  - `records` 新增、删除，或 `status` 变化；
  - `users` 新增、删除，或者 `username`、`display_name`、`is_participant`、`score` 变化；
  - `weekly_reports` 新增或改写。
- 机器人启动时也排一次。
- 实际延迟约 10–40 秒：事件排在 10 秒后，dispatcher 最长每 30 秒轮询一次。
- **怎么发：** 已经发过、频道也没变，就原地编辑。频道变了：删掉旧消息，在新频道发一条。消息被删了（Discord 返回 10008/10003）：重新发一条。
- 时间全部用 Discord 相对时间戳显示，所以不需要定时刷新。

## 8. 规则汇总

**隐私：**
- 判决前脱敏不变。
- 分数公开，段位只给本人看。
- 网页、信息板和接口一律不暴露 `discord_*`。
- 语音记录只给裁判、管理员和本人看。

**解除的 v5 锁定**（下面这几条随约局一起删除）：
- 「单一 /约局/ 标题」；
- 409 提示「约局时间已经改了…」；
- `?session` 的跳转行为：改成落到首页并提示，参数本身仍然永久兼容。

**新增的固定文案：**
- 「约局功能已下线」；
- 「约人直接在 Discord 里喊；迟到、放鸽子由裁判记录。」；
- 「约局功能已下线，这个按钮不再有效。」；
- 「这段时间机器人不在线，没有记录不代表没来。」；
- 语音告知：「绑定后，你在本服务器语音频道的进出时间会被记录，保存 90 天，供裁判处理迟到、缺席时参考。只有裁判、管理员和你自己能看到。」（天数取自 `VOICE_RETENTION_DAYS`）。

**其他 v5 规则照旧：** CSP（不准内联样式和 `dangerouslySetInnerHTML`）、DOM 顺序就是视觉顺序、组件签名只能加可选 props、接口返回 404 时新入口静默隐藏、D1 和 PG 行为一致。
