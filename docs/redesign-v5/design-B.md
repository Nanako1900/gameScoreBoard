> 依据：`analysis.md`（下文简称「分析」）以及 raw.json。关键细节都回到代码核对过：`worker/sessions.ts`、`server/migrations/0005_sessions.sql`、`server/src/discord/sessions.ts`、`server/src/discord/commands.ts`、`src/App.tsx`、`tests/dom/*`。

## 1. 一句话概念，以及为什么适合这群人

**一句话**：首页改成一个开黑大厅，第一眼看到的是「今晚谁组了局、谁会来、哪一局在等你回」。信誉分不再站在台上，而是挂在每个人名字旁边当背景信息。产品主张是**「先约上，再守约」**。

**为什么适合**（对应分析 §1）：

- **按来访频率，大家主要是为约局来的。**
  - 选手「每周几次，被立案或被约时集中来」。这里面「被约」是常态，「被立案」只在出事时发生。
  - 组织者可以是任何登录用户，每次组局都要来一趟，是最高频的写操作角色。
  - 裁判和管理员「出事时 / 有申诉时」才来。
  - 结论：现在把 82% 的首屏让给红黑榜和战报，是按低频场景排的版。
- **Discord 已经在把人往网页送，网页却接不住。**
  - `/yue` 发起后回一句「在网页上可以看到它、邀请人」（`discord/sessions.ts:276`），可网页建完局就没法再叫人（H11）。
  - 改期的后端早就做好了，却没有入口（H12）。
  - 所以网页最该补的「重操作工作台」，恰好就是约局。
- **规模小，适合做「熟人大厅」，不适合做「排行榜站」。**
  - 13 个账号、9 人上榜，「谁会来」可以把头像和名字全部铺开，不需要搜索和筛选。
  - 信誉分最有用的时候，是组局前看一眼「这桌人靠不靠谱」。分数放在名单旁边，比放在排行榜上更像它本来的用途：守约的工具，不是羞辱的舞台。
- **分享的天然单位是一局。**
  - 分析 §1 里网页的第 2 个职责是「能分享的公开版面」。在这群人里最常被转发的是「周五 21:00 五排还差 1 人」。
  - 所以把 `/sessions/:id` 做成一张完整、能分享、未登录也看得懂的页面，等于同时解决了 H1、H3 和 4.2 里的「分享链接本身就是邀请」。
- **语气原则天然落在对的地方。** 大厅里的内容（约局、人齐、再约一次）可以尽情玩梗；扣分和案件退到选手页与「审理」页，放软语气更容易做到。

## 2. 信息架构

### 2.1 导航骨架

- **手机**：底部固定 3 个标签，加一个居中的「＋ 组一局」按钮。
  - 标签是 `大厅`、`信誉榜`、`我的`。
  - 裁判或管理员会多一个 `审理` 标签，带待办角标，一共 4 个。
- **桌面**：顶部 Header 里放同样的标签链接，加上「＋ 组一局」按钮。
- **路由**：手写 `src/lib/router.ts`，约 80 行，用 pushState 和 popstate，暴露 `<Link>`、`useRoute()`、`navigate()`。不引入依赖。
  - 浮层也入栈：打开 sheet 时 `pushState(state.sheet)`，所以 Android 返回键关掉的是当前浮层。
  - 路径不能用 `/api`、`/auth`、`/link` 开头，也不加 404.html。Pages 的 SPA 回退会照常返回 index.html。

### 2.3 旧深链映射（永久兼容）

**统一规则**：

- 启动时用 `readDeepLink`（不改）读一次参数，然后**立刻**用 replaceState 把参数从 URL 去掉。
- 目标先暂存在内存里，等首次登录引导关掉以后再跳转。这和现在 `onboardingAsked` 的语义一致。
- 链接本身从不写数据。

| 旧链接 | 新行为 |
|---|---|
| `/?session=N` | replaceState 到 `/sessions/N`，search 变成空串，`deep-link.test` 断言的 `location.search === ''` 仍然成立 |
| `/?case=N` | 先 `GET /api/records/N`，再 replaceState 到 `/players/<subject>/cases/N`：选手页打开，案件卡加上 `vc--focus`，并 `scrollIntoView({block:'center'})`。返回 404 时留在 `/`，显示「链接里的案件不存在了。」；返回 500 时显示「打不开链接里的案件，稍后再试。」 |
| `/?linked=discord[&onboarding=1]` | 只去掉 `linked`，`?onboarding=1` 留给引导逻辑消费，和测试一致。大厅顶部显示 `DiscordLinkedNotice`「Discord 绑定成功」，附「关闭提示」按钮，新增一个链接「去设置私信 →」指向 `/me/notify` |
| `/?onboarding=1` | 首次登录引导以 sheet 形式盖在大厅上，优先级高于深链 |
| Bot 新链接（可选，P3） | `/sessions/N/invite`，可以在 `/yue` 的回复里直接给出。旧格式仍然是主格式 |

### 2.4 登录回跳（解决 H3，纯前端）

- **跳登录前**：任何「登录后报名」「登录」按钮在跳转前，先写入 `sessionStorage['edg.return'] = {path, intent, at}`。
  - `intent` 只可能是 `rsvp:going|maybe|out` 或 `none`。
  - 有效期 15 分钟。
- **回来后**：登录回到 `/`（新用户带 `?onboarding=1`）。引导关掉之后，路由跳到 `path`。
- **不自动报名**：页面上用金色描边圈出用户之前选的那个按钮，并写一句「你登录前点的是『来』，确认一下？」。用户自己再点一次才写入，遵守「A link never writes」。
- **不改后端**：登录是同一个标签页里的顶层跳转，sessionStorage 能保留。`safeNextPath` 维持只认 `/link/*`，后端不动。

## 4. 邀请功能整合方案

### 4.1 统一数据源

- 新增 `useSessions()` 资源（在 `src/lib/resource.ts` 的 `useResource` 之上），把三类数据合成一份 `Map<id, SessionItem>`：
  - `/api/sessions?scope=upcoming`（首屏原有请求，URL 不变，测试依赖它）；
  - `/api/me/invites`；
  - `/api/sessions?scope=past&limit=20`（新增，拿进行中和最近结束的局，失败静默降级）。
- 大厅、详情页、Toast 读的都是这一份数据。报名先乐观更新，再用返回的 session 覆盖。
- 页面重新可见时（visibilitychange）重新拉取；大厅可见时每 60 秒拉一次。
- 返回 503（只读维护）时显示「系统维护中，暂时不能报名」，整页不切到错误态（M11）。

### 4.2 生命周期：网页交互、文案、Bot 对齐

| 步骤 | 网页交互与文案 | Bot 对齐 |
|---|---|---|
| **创建** | `/sessions/new`：时间 chip 按看板时区，叫人分「上次一起的 / 上榜选手 / 其他朋友」，「和上次一样」，可设人数上限、游戏、备注。按钮「约！（叫 N 人）」。成功后：「局已发起 🎮 把链接发到群里」 | `/yue` 不改流程，回复里那句「在网页上可以看到它、邀请人」终于成真。可选：回复里的链接直接指向 `/sessions/N/invite`。权限对齐见 4.4 |
| **邀请** | 建局时勾选，或者事后在 `/sessions/:id/invite`「再叫几个人」。已在局里的、说了不来的置灰。Toast：「已叫 2 人。Bot 会私信绑了 Discord 的人。」 | 新接口 `POST /api/sessions/:id/invite` 插入 `invited` 行，PG 触发器 `session_players_outbox` 会自动发 `dm.session.invited`，**bot 不用改**。额度照旧：同一组织者对同一人每天 3 条，每人每天约局私信 10 条 |
| **通知** | 网页上就是大厅里的「等你回」卡片和标签页标题的计数，不做浏览器推送。没绑 Discord 的人：TodoStrip 里显示一条可关闭的提示「绑定 Discord 后，邀请会直接私信给你 ›」 | 私信和频道卡片不变。网页文案统一成 bot 的说法：「XX 约你：…」 |
| **报名** | `RsvpControl`：来 / 待定 / 不来，用 `RSVP_LABEL`，全站一致。带上看到的 `starts_at`；返回 409 时先刷新，再显示「约局时间已经改了，请按新的时间重新确认」。成功后 Toast「已登记：来 · 现在 4/5 人 [撤销]」。只有之前是来、待定或不来时才提供「撤销」；之前是 invited 的，用户不能自己改回去，所以改为提示「改主意了随时可以改」。满员时「来」置灰，旁边写「满了，可以先报待定」 | **bot 的标签「可能」改成引用 `shared/attendance` 的「待定」**（`server/src/discord/sessions.ts:36`，一行改动），网页和 bot 用词一致 |
| **提醒** | 详情页「加到日历」：前端用 Blob 生成 `.ics`，带开局前 15 分钟的 VALARM，补上没绑 Discord 的人收不到提醒的缺口。我答应的局，开局前 1 小时内卡片显示倒计时「还有 42 分钟」 | 开局前 15 分钟的私信不变 |
| **改期** | `/sessions/:id/reschedule`，调用现有的 `PATCH`。确认文案见 3.6。被影响的人在大厅里看到「↻ 改时间了 · 你之前说『来』 / 原时间 → 新时间 / 新时间还来吗？」 | 和 `dm.session.changed`「🔁 约局改时间了」用同样的措辞。后端要新增 `prev_rsvp`、`prev_starts_at`，网页才能写出「你之前说『来』」 |

3. **`/join` 落地页**：

   - 「先看看」是在现有身份 radiogroup「选择身份」里新增的一项，保存为 `is_participant=false, is_judge=false`。`/api/me/roles` 已经支持。
   - 原有三项和它们的文案不变（`onboarding-roles.test`）。
   - 首次登录的引导说明也跟着补一句：「上榜之后，分数会公开显示在榜上」（M21）。
4. **Discord 服务器邀请和绑定**：都收进 `/me/notify` 的三步。`DiscordLinkCard` 里那句好处的文案改成「约局邀请和开局提醒会私信给你，在私信里一键报名」。
5. **新人上榜**：`/join` 加上「先看看」以后，上榜成为自愿而且清楚的选择。不在榜上的人也能被邀请（`GET /api/users/invitable`）。点名时他们出现在「没回 / 待定」或「答应来的」分组，带「未上榜」标签，不生成记分草稿，这是后端现有规则。

**方向 B 额外加的人性化点**：

- **人齐了**：满员时卡片角标「满员 🎉」，组织者控制台写「5/5 到齐，就等开打」。

- **未上榜的人不被区别对待**：名单里显示「未上榜」，而不是空白或 0 分。
- **「不来」不是坏事**：「不来」用中性灰，不用红色；开局前说不来，名单上会显示「提前说了 ✓」。

**语气原则在每个场景的落地**：

## 6. 视觉方向

**保留**：

- 深色电竞转播风；
- 4 级表面（`--bg`、`--bg-elevated`、`--panel`、`--panel-2`）；
- 圆角和动效 token；
- Rajdhani 作为数字和拉丁字母的展示字体；
- `color-scheme: dark`；
- `pointer:coarse` 时触控目标 ≥ 44px；
- reduced-motion 降级；
- 「选中状态不只靠颜色」（`aria-pressed` 加 ✓ 或描边）。

**不做浅色模式**。分析 §9 的第 10 个问题，这个方向的回答是：先把深色做对。浅色模式要双倍的视觉验收，群体规模小，收益也低。token 拆成两层以后，以后要加只需要再写一层语义 token。

**token 拆成两层**：

- `primitives.css`：`--gold-500`、`--green-500`、`--amber-500`、`--red-500`、`--blue-500`、`--grey-*`。
- `semantic.css`：

| 语义 token | 用途 | 说明 |
|---|---|---|
| `--action` | 金色：主操作、「等你回」 | 金色从 7 种含义收到这 2 种（M24） |
| `--rsvp-going` | 绿色：来、准时、满员 | |
| `--rsvp-maybe` | 琥珀：待定、改时间了、截止临近 | |
| `--rsvp-none` | 中性灰：没回、不来、已取消 | 不来不用红色 |
| `--danger` | 红色：只用在危险按钮和扣分数字上 | 永远不用来给人上色 |
| `--info` | 蓝色：Discord、链接、AI 来源 | |
| `--score-chip-bg` / `--score-chip-fg` | 分数 chip | 对所有人用同一个中性色，不按段位上色 |

- 段位色只出现在本人的 `MyScoreCard` 和 `TierBadge` 上，而且每一档都配 emoji 和名字。两档对比度只有 1.15:1 的颜色（`#f5c542` 和 `#f0b429`，`scoring.ts:175,178`）要把「需要盯一下」改成更偏橙的颜色，做到相邻两档亮度差 ≥ 1.5:1。这是 `shared/scoring.ts` 的改动，bot 用不到这些颜色。
- 本人视角的段位说明在 `TIERS` 里新增 `selfHint` 字段，原来的 `blurb` 不再用于展示（M6），例如「资深鸽王 → 最近有点难约。守约几局，分数会回来的。」。

**H8 层叠顺序**：

- `main.tsx` 改成先 `import './theme.css'`，再 `import App`。
- 用 `@layer reset, tokens, base, components, utilities;` 明确层级，组件 CSS 包进 `@layer components`。
- 这样弹窗阴影、绑定按钮的蓝色、撤销按钮的红色、胶囊圆角都会回来。

**H9 焦点环**：

- 全局 `:focus-visible { outline: 2px solid var(--focus-ring); outline-offset: 2px; }`，`--focus-ring` 用亮青色，在金色按钮上也看得清。去掉所有 `outline:none` 加 box-shadow 的写法。
- `@media (forced-colors: active)` 下 outline 用 `Highlight`，按钮和输入框边框用 `ButtonText` 或 `CanvasText`，状态 chip 加边框，保证不依赖背景色也能看出来。

**H10 对比度**：

- `--faint` 从 `#5c6675` 提到 ≥ 4.5:1，在 `--panel-2` 上约 `#8691a2` 一档，原 `--muted` 再相应提亮。
- 输入框边框 `--border-input` ≥ 3:1（非文字对比度标准）。
- 规定 `--faint` 只用于装饰，「未回应」、隐私告知、截止时间一律用 `--muted` 以上。
- 在 `tests/unit` 里加一个 token 对比度单测（算 WCAG 对比度），防止以后回退。

**M25 字号与字体**：

- 收成 6 级：12 / 14 / 16 / 18 / 22 / 28px，展示用的 hero 级只留给 `MyScoreCard` 的分数。
- 中文最小 12px（0.75rem），输入框 ≥ 16px。
- `--font-display` 只负责数字和拉丁字母，栈尾补中文：`'Rajdhani', 'PingFang SC', 'Noto Sans SC', 'Microsoft YaHei', system-ui`。
- P3 自托管 Rajdhani 的 woff2 子集，`font-display: swap`，并从 CSP 里去掉 Google Fonts（见 §9 对测试的影响）。

**密度**：

- 大厅卡片每张约 150–190px 高，375px 宽的首屏能看到 TodoStrip 和 1.5 张「等你回」卡。
- 名单最多一行 4 个名字加「+N」；完整名单在详情页。

**图标**：

- 语义图标从 emoji 改成内联 SVG 组件 `src/components/icons/*.tsx`，大约 12 个：等你回、改期、进行中、点名、满员、分享、日历、Discord、警示、回血、审理、加号。
- SVG 是 JSX，不用内联 style，CSP 不变。
- emoji 只留在玩梗的地方：🎉、🎮、空状态。
- 出勤标签保留 `ATTENDANCE_DEFS` 里的 emoji 加文字，因为它们来自 shared，bot 也在用。

**M24 其他问题**：红卡配蓝环的问题，随 `RedBlackBoard` 一起删掉；`StarOfWeek` 只用金色。

## 10. 风险与取舍

1. **计分板退出首屏。** 想来看排名、看热闹的人要多点一下。红黑榜作为「梗的主舞台」没有了：黑榜彻底不做，只留有门槛的本周之星。喜欢「头号鸽王」这种玩法的群友会觉得网页变正经了。补偿是梗转移到约局和战报正文里。
2. **公开段位变成只显示分数。** 这遵守 v4「段位只给本人看」，但和方向 B「名单里看到段位」的字面描述不一致，也会让 Leaderboard 上的段位徽章对他人消失。如果业主更想要段位，改动成本很低（换一个 chip），但需要先拍板，并且和 bot 保持一致。
3. **约局少的时候大厅显得空。** 这个方向押注约局频率。如果某周只有 0–1 局，首页就只剩空状态和成员条。缓解办法：用空状态文案加「组一局」引导，成员条和战报摘要兜底。但「冷清」的观感确实存在。
4. **网页依旧不是实时的。** 不做 WebSocket 和推送，只在页面可见时轮询，加 visibilitychange 刷新。真正的「来了一条邀请」仍然靠 Discord 私信。没绑 Discord 的人要靠 `.ics` 和自己打开网页，这是有意的取舍：通知归 Discord，网页不再当提醒器（分析 §1）。
5. **组织者知道的信息有限。** 为了不暴露谁绑了 Discord，「多少人能收到私信」只在至少 3 人时给出聚合数字，组织者没法知道某个人一定收到了。只能用「把链接发到群里」这种人工兜底。
6. **一局一张 OG 预览做不到。** 前端在静态 Pages 上，又不想复活遗留的 Pages Functions。分享到微信或 Discord 时，预览只能是全站统一文案，看不到「周五 21:00 还差 1 人」。文字信息靠 `navigator.share` 的 text 字段补。
7. **路由和页面变多，实现和维护成本上升。** 从 1 个页面加一堆弹层，变成约 15 条路由，加上 sheet 入栈的历史管理。手写路由要自己处理滚动恢复、焦点还原和 Android 返回键，相关 bug 会多一些。P0 要专门留出验收时间（实机测 iOS Safari 和 Android Chrome）。
8. **双后端维护负担。** ★5、#15 这类只在 Node 上实现的接口，会让遗留的 D1 Worker 和 Node 的能力进一步分叉。前端必须保证所有新入口在接口返回 404 时静默隐藏，每加一个都要写一条降级测试。
9. **改期会重置所有人的报名。** 这是后端现有的正确规则。但随着大厅把「改时间」做得很顺手，组织者可能更频繁地改，带来更多重新确认和私信，去重后每人每段时间只发一条，但额度每天 10 条。缓解：确认文案写明影响人数；不提供「静默改期」。
10. **放弃了什么**：不做浅色模式；不做固定周期局（用「再约一次」代替）；不做 invite token 和「谁拉你来的」；不做连胜、请假、延期；不做分数账本页（用走势图的原因注释代替）；不做 walk-in 和报名留言（放到 P3 可选，而且要先评估刷分风险）。
